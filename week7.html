Week 7

Real-Life SQL Project

Solving a real problem with SQL

Welcome to the Final Week!

You've learned tables, queries, aggregates, grouping, sorting, and joins. Now it's time to put it all together in your own project.

This week, you will design your own database to solve a real problem. Your teacher will give you a set of data, and you will decide how to organize it, query it, and present your findings.

This is what real data analysts do every day — turn raw data into insight that helps people make decisions.

Learning Outcomes

By the end of this week, you will be able to:

Higher Order Thinking Skills (HOTS)

CREATE Design and build your own database from a given dataset — deciding on tables, columns, keys, and relationships that best fit the data.
ANALYZE Analyze the given data to identify meaningful questions and write SQL queries that reveal patterns, rankings, and summaries.
EVALUATE Evaluate your own design and findings — justify your table structure, query choices, and explain the value your database brings to a real-life scenario.

What You'll Do This Week

You will complete a project that combines everything you've learned. It has four parts:

1. Design Your Database

Decide which tables and columns you need. Plan before you type.

2. Import the Given Data

Your teacher will give you a dataset. Import it into your database or type the SQL to create the tables.

3. Write Meaningful Queries

Answer at least 5 real questions using SELECT, WHERE, COUNT/AVG/SUM, GROUP BY, ORDER BY, LIMIT, and JOIN.

4. Present Your Project

Show your database, run your queries live, and explain the value your design brings.

This is your chance to be the analyst. Don't copy the sample queries — think about what questions your data can answer.

Step 1: Design Your Database

Before you write a single line of SQL, plan your design on paper.

Ask yourself:

  • What are the main things in my data? (students, items, sales)
  • What columns does each table need?
  • Which column is the primary key?
  • How do the tables connect? (foreign keys)

Sample ER diagram (as text)

Design 
students
  ├── id (PK)
  ├── name
  ├── grade
  └── section

subjects
  ├── id (PK)
  ├── name
  └── teacher

scores
  ├── id (PK)
  ├── student_id (FK → students.id)
  ├── subject_id (FK → subjects.id)
  └── score
Draw your design on paper first. A good design makes queries easy. A bad design makes everything hard.

Step 2: Build Your Tables

Once your design is ready, create the tables in phpMyAdmin.

SQL 
CREATE TABLE students (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(50),
  grade INT,
  section VARCHAR(10)
);
SQL 
CREATE TABLE subjects (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(50),
  teacher VARCHAR(50)
);
SQL 
CREATE TABLE scores (
  id INT AUTO_INCREMENT PRIMARY KEY,
  student_id INT,
  subject_id INT,
  score INT,
  FOREIGN KEY (student_id) REFERENCES students(id),
  FOREIGN KEY (subject_id) REFERENCES subjects(id)
);
Import the data your teacher gives you using phpMyAdmin's Import tab, or insert it with INSERT INTO.

Step 3: Write Meaningful Queries

Your project must include at least 5 queries that answer real questions. Use a mix of skills you've learned.

Required query types (at least one of each):

  • A SELECT with WHERE — filter rows
  • A COUNT, AVG, or SUM — summarize data
  • A GROUP BY — compare groups
  • An ORDER BY with LIMIT — rank results
  • A JOIN — combine two or more tables

Sample query set (Grade Analytics theme)

Query 1 — Filter 
SELECT name, grade FROM students
WHERE grade = 10;
Query 2 — Summarize 
SELECT AVG(score) AS avg_score
FROM scores;
Query 3 — Group 
SELECT subject_id, AVG(score) AS avg_score
FROM scores
GROUP BY subject_id;
Query 4 — Rank 
SELECT student_id, SUM(score) AS total
FROM scores
GROUP BY student_id
ORDER BY total DESC
LIMIT 5;
Query 5 — Join 
SELECT students.name, subjects.name AS subject, scores.score
FROM scores
JOIN students ON scores.student_id = students.id
JOIN subjects ON scores.subject_id = subjects.id;
Write a one-sentence explanation for each query — what question does it answer?

Step 4: Present Your Project

On the final day, you'll present your project to the class in 3–5 minutes.

What to include:

  1. Problem: What real-life problem does your database solve?
  2. Design: Show your tables and how they connect.
  3. Queries: Run at least 3 of your queries live.
  4. Findings: What did your data reveal?
  5. Value: Who benefits from your database?
Show your queries live in phpMyAdmin. It's more impressive than slides — and it shows real skill.

Submission Checklist

Before you submit, make sure you have all of these:

  • A written design of your database (tables, columns, keys)
  • All tables created in phpMyAdmin
  • The provided data imported or inserted
  • At least 5 SQL queries saved in a text file or document
  • A one-sentence explanation for each query
  • Your presentation notes (3–5 minutes)
  • A short reflection on what you learned

Quick Check

Answer these before presenting:

  1. What problem does your database solve?
  2. How many tables did you create, and how are they linked?
  3. Which query are you most proud of, and why?
  4. What did your data reveal that you didn't expect?
  5. Who benefits from your database in real life?

Project Rubric

Your final project will be graded using the rubric below. The highest possible score is 50 points.

Criteria Excellent (10) Good (7) Fair (4) Needs Work (1)
Database Design Tables, columns, and keys are well-planned, logical, and clearly documented. Design is mostly logical with minor issues. Design is incomplete or poorly organized. No design or design does not match data.
Table Creation & Data Import All tables created correctly; provided data imported without errors. Tables created; minor issues with data import. Some tables missing or data incomplete. Tables not created or data not imported.
SQL Queries (5+ required) Queries are correct, varied, and meaningfully answer real questions. Uses SELECT, WHERE, aggregates, GROUP BY, ORDER BY, LIMIT, and JOIN. Queries are correct but lack variety or depth. Fewer than 5 queries or several are incorrect. Queries missing or mostly incorrect.
Presentation Clear, confident, well-organized presentation that explains the design, queries, findings, and value. Clear presentation with minor gaps. Presentation is unclear or incomplete. No presentation or did not explain the project.
Reflection & Value Thoughtful reflection that clearly explains what was learned and how the database adds real value. Reflection is present but brief. Reflection is vague or missing key points. No reflection submitted.
Total Possible Score: 50 points
